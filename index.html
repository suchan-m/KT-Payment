Slide 03 | System overview

ระบบที่เชื่อมต่อกัน

Vendor→VMCS
Login / Sign Up / Portal→POTS
Account & Payment←SAP
Invoice / Vendor MasterAuthentication

VMCS เป็นจุดเริ่มต้น

  • Vendor เข้าใช้งานและลงทะเบียนผ่าน VMCS
  • VMCS ส่ง Create / Update / Inactive Account ไปยังระบบปลายทาง

PTS ประมวลผลข้อมูลธุรกิจ

  • ดึง Invoice และ Vendor Master จาก SAP
  • ทำ filter และ data conversion ก่อนบันทึก Database

Slide 04 | Requirement

Requirement: SAP Data, PTS และ VMCS

Structure มีการเปลี่ยนแปลง โดย SAP เตรียมข้อมูลตาม Standard และ PTS เลือกเฉพาะฟิลด์ที่จำเป็นต่อการใช้งาน

Data structure ที่ต้องรองรับ

  • ปรับจำนวนคอลัมน์ตามข้อมูล Standard จาก SAP
  • ปรับ Field Type, Length หรือ Property อื่น ๆ ที่เกี่ยวข้อง
  • ค่า Code ที่ Map บน PTS อาจเปลี่ยน เช่น Payment Block และ Payment Method จึงต้อง Initial Master ใหม่

Integration และการใช้งาน

  • PTS ส่ง Filter ไปยัง SAP เพื่อดึงเฉพาะข้อมูลที่ต้องใช้
  • ทำ Data Conversion ก่อนบันทึกข้อมูลลง Database ของ PTS
  • Vendor ใช้งาน Portal และ Landing Page ผ่าน VMCS เพื่อเข้าสู่ Application PTS
  • Share OutSystems Block หรือ Component อื่น ๆ เพื่อให้ VMCS เรียกใช้งานได้

Slide 06 | Account API

Create / Update Account

Contract

  • Method: POST
  • Endpoint: /VMCS/CreateUpdateAccount
  • Authorization: Bearer Token
  • Content-Type: application/json

Responsibility

  • Consumer: VMCS
  • Provider: SWR, PTS/POTS
  • ใช้สร้าง แก้ไข หรือยกเลิกสิทธิ์ Vendor Account
  • บันทึกเวลา request เพื่อใช้เทียบ Log ทุกครั้ง

ห้ามแนบ Bearer Token, Password หรือ Secret แบบไม่ปกปิดใน Ticket และ Email
