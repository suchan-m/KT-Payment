Slide 01 | Knowledge transfer

VMCS / Payment Tracking (PTS)

Support Handover Guide

25 August 2026

Slide 02 | Agenda

Scope ที่ Support ต้องดูแล

  • ภาพรวมระบบและ Scope
  • การเชื่อมต่อ VMCS / PTS / SAP / Authentication
  • Vendor functions และการเปลี่ยนแปลงสำคัญ
  • Create / Update Account API

Slide 03 | System overview

ระบบที่เชื่อมต่อกัน

Vendor→VMCS→PTS→SAP
  • VMCS เป็นจุดเข้าใช้งานหลักของ Vendor
  • PTS รับข้อมูลธุรกรรมและ Vendor Master จาก SAP

Slide 04 | Key changes

Payment Tracking (PTS)

  • รองรับ SAP field, length และ code mapping ใหม่
  • เพิ่ม API Vendor Create / Update / Inactive
  • ย้ายข้อมูลไป Database structure ใหม่
  • ปรับ shared component ให้ VMCS เรียกใช้ได้

Slide 05 | Vendor functions

ฟังก์ชันที่ควรรู้

Loginใช้ OpenID ของ VMCSRegistrationย้ายไป Sign Up บน VMCSInvoiceList / Export ยังใช้งานFAQsอาจอยู่ PTS หรือรวมกับ VMCS

Slide 06 | Account API

Create / Update Account

  • POST /VMCS/CreateUpdateAccount
  • Authorization: Bearer Token
  • VMCS ส่งข้อมูลไปยัง PTS
  • ตรวจ vendorCode, companyCode, userAccount และ accountStatus

Slide 07 | API response

Error code ที่ต้องตรวจ

200ตรวจ User / Vendor ปลายทาง400 / 401Header, Payload, Token, Client500Application log / dependency503Service, network และ retry

Slide 08 | Troubleshooting

Incident matrix

  • Login ไม่ได้: VMCS → Account Active → Token/Auth
  • Create/Update ไม่เข้า: Payload → Response → Log → DB
  • Invoice ไม่ขึ้น: SAP API → Filter → Conversion → DB
  • 401: Auth/MuleSoft; 500/503: App/Infra

Slide 09 | Support runbook

ก่อน Escalate

  • เก็บ User Email, Vendor Code, Company, เวลา และ screenshot
  • ระบุ flow: Login / Sync / Invoice / SAP
  • ตรวจ response code และ application log
  • API สำเร็จแต่ข้อมูลไม่เปลี่ยน: ตรวจ DB และ PTS logic

Slide 10 | Support notes

ข้อควรระวัง

  • ห้ามส่ง Bearer Token, Password หรือ Secret แบบไม่ปกปิด
  • ระบุให้ชัดว่าปัญหาเกิดที่ VMCS หรือ PTS
  • ปัญหาหลัง migration: แยก source, mapping, conversion และ migration
  • SAP เปลี่ยน structure: ตรวจ type, length และ mapping ก่อน
